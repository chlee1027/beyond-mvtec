# PatchCore — Towards Total Recall in Industrial Anomaly Detection (요약)

> **한 줄.** ImageNet 으로 배운 CNN 을 얼린 채 중간 단계(layer2 · layer3) 특징을 3x3 이웃으로 평균한 **조각 특징**을 정상 이미지 전부에서 모아 기억 뱅크 하나에 넣고, 탐욕 코어셋으로 1~25% 만 남긴 뒤, 시험 조각마다 뱅크 최근접 거리를 재서 **가장 먼 조각의 거리**를 이미지 점수로 쓰는 방법이다. MVTec AD 에서 WRN-50 (2,3) 코어셋 10% 가 이미지 AUROC 99.0 · 픽셀 AUROC 98.1 · PRO 93.5 다. **이 레포 Q1 격자 여덟 칸 중 논문이 직접 잰 칸은 WRN-50 (2,3) 의 10% · 1% 둘뿐이고, ResNet18 은 논문 표에도 원 저자 코드의 백본 목록에도 없다.**

## 용어

- **조각 특징 (patch feature)**: 특징 지도 한 칸 $(h, w)$ 의 벡터. 예: 224 입력의 WRN-50 layer2 격자는 28 x 28 이라 이미지 하나가 조각 784 개다(내가 센 것).
- **단계 (hierarchy level) $j$**: ResNet 꼴 망에서 해상도가 같은 블록 묶음의 끝 출력. $j$ = 1, 2, 3 이 torchvision 의 `layer1` · `layer2` · `layer3` 이다. 이 레포의 「층 (2,3)」 이 논문의 「hierarchies 2+3」 이다.
- **이웃 크기 (patchsize) $p$**: 조각 특징 하나를 만들 때 평균하는 정사각 이웃의 한 변. 이미지 조각 크기가 아니다. 예: $p$ = 3 이면 격자 9 칸을 평균한다. 이 레포 설정의 `neighborhood: 3` 이다.
- **기억 뱅크 (memory bank)**: 학습 이미지의 조각 특징을 모은 집합. 부류마다 하나.
- **PatchCore-n%**: 뱅크를 n% 로 줄인 것. 표에 따라 `PatchCore-10` 으로도 적는다(같은 것). 예: 1% 는 100 배 축소.
- **코어셋 (coreset)**: 큰 집합에서 고른 작은 부분 집합. 여기서는 「지금까지 뽑힌 점에서 가장 먼 점을 하나씩 더하는」 탐욕 뽑기로 고른다.
- **이미지 AUROC · 픽셀 AUROC · PRO**: 이미지 점수 / 픽셀 점수로 정상과 이상을 가르는 ROC 곡선 아래 넓이, 그리고 결함 연결 성분마다 겹침을 재는 분할 지표. MVTec 은 부류마다 재서 15 부류를 평균한다. **PRO 의 정의는 이 논문에 없고 Uninformed Students 논문에 미룬다.**
- **적은 표본 (low-shot)**: 부류마다 정상 학습 이미지를 1 ~ 50 장만 쓰는 설정. 이 레포 Q2 와 같은 꼴이다.

## 문제 / 동기

**적응 없이 ImageNet 특징을 맞대는 방법(DN2 · SPADE · PaDiM)의 두 약점을 고친다.** 논문이 적은 약점: (1) 높은 단계 특징은 ImageNet 분류 쪽으로 치우쳐 공장 이미지와 겹치는 부분이 적다. (2) 이미지당 높은 단계 특징의 개수가 적어 시험 때 쓸 정상 맥락이 적다. 목표 셋은 정상 정보를 최대로, ImageNet 치우침을 작게, 추론은 빠르게. PaDiM 과의 차이로 논문이 적은 것: PaDiM 은 위치마다 따로 가우스를 두므로 정렬에 기대고 학습 · 시험 크기가 같아야 하지만, PatchCore 는 모든 시험 조각이 뱅크 전체와 비교되므로 정렬에 덜 기대고 크기가 달라도 된다(2절). 이 주장은 MTD(크기가 제각각인 데이터)에 PatchCore 를 돌린 것으로만 뒷받침되고, 정렬을 바꿔 가며 잰 실험은 없다.

## 핵심 기술

**① 국소 이웃 집계 (3.1절, 식 1~3).** 단계 $j$ 와 $j+1$ 두 개의 특징 지도에서 칸마다 $p$ x $p$ 이웃을 적응 평균 풀링으로 묶는다. 윗단계는 양선형으로 늘려 아랫단계 격자에 맞춘다. 결과는 「미리 정한 차원 $d$」 의 벡터라고만 적고 $d$ 값은 없다. 기본값은 WRN-50, 단계 2+3, $p$ = 3, 보폭 1.

**② 탐욕 코어셋 (3.2절, 식 5, 알고리즘 1).** 뱅크의 모든 점이 가장 가까운 뽑힌 점까지 가는 거리의 최댓값을 줄이는 집합을 탐욕으로 고른다. 고르는 시간을 줄이려고 무작위 선형 사영으로 차원을 낮춘 공간에서 고른다. 사영 차원과 첫 점을 고르는 법은 논문에 없다.

**③ 점수 (3.3절, 식 6 · 7).** 이미지 점수는 시험 조각별 최근접 거리의 최댓값에 이웃 $b$ 개로 낸 재가중을 곱한 것. 분할 지도는 조각 점수를 제자리에 펼쳐 양선형으로 늘리고 폭 $\sigma$ = 4 가우스로 흐린 것. $b$ 값은 없다.

**설정과 장비.** 256 으로 줄이고 가운데 224 를 자른다. 증강 없음. Python 3.7 · PyTorch, 가중치는 torchvision 과 timm, 최근접 탐색은 faiss, GPU 는 「Nvidia Tesla V4」(부록 A 표기 그대로). 반복 수와 시드는 적혀 있지 않다.

**공개 코드에서 읽은 값 (논문에 없는 것).** 코드 기본 명령 기준이다.

| 논문에 없는 값 | 공개 코드 |
|---|---|
| 조각 특징 차원 $d$ | `--pretrain_embed_dimension 1024 --target_embed_dimension 1024`. 단계마다 ($C$ x $p$ x $p$) 를 펼친 벡터를 1-D 적응 평균 풀링으로 1,024 로 맞추고, 두 단계를 쌓아 다시 1,024 로 풀링한다. 곧 $d$ = 1,024 이고, 512 + 1,024 를 이어 붙인 1,536 이 아니다 |
| 사영 차원 $d^*$ | 128 (`dimension_to_project_features_to=128`, 편향 없는 `torch.nn.Linear` 의 무작위 초기화) |
| 코어셋 첫 점 | `approx_greedy_coreset`: 무작위 10 점(`np.random.choice`)까지의 평균 거리가 가장 큰 점. `greedy_coreset`(정확판)은 무작위 없이 거리 행렬 행 노름이 가장 큰 점 |
| 재가중 이웃 수 $b$ | 식 (7) 재가중이 코드에 없다. 점수는 최근접 $k$ 개 거리의 평균이고, 이미지 점수는 조각 점수의 최댓값이다 |
| 가우스 $\sigma$ | 4, 단위는 입력 픽셀(늘린 뒤의 224 x 224 지도에 `scipy.ndimage.gaussian_filter`) |

## 이 레포 실험에 가져갈 것

**하나. 재현 목표와 원 저자 코드가 보고한 값.** README 의 재현 목표(PatchCore-10% 99.0 · 98.1 · 93.5, PatchCore-1% 99.0 · 98.0 · 93.1, PaDiM 95.3 · 97.5 · 92.1)는 표 1 · 2 · 3 과 맞다. 원 저자 코드의 README 는 같은 설정(WR50, layer2 · layer3, 10%, 224, 시드 0)을 「WR50-baseline 99.2% · 98.1% · 94.4%」 로 보고하고, 이는 공개 모델 `IM224_WR50_L2-3_P01_D1024-1024_PS-3_AN-1` 의 `results.csv` 평균(이미지 99.16 · `full_pixel_auroc` 98.11 · `anomaly_pro` 94.37)과 맞는다. 묶기 모델(IM320, 시드 40)은 99.6 · 98.2 · 94.9.

- **이미지 AUROC 는 코드 값이 논문보다 0.16 ~ 0.24 높다**(99.16 대 99.0, 표 S1 부류 평균 98.927). 부류별로는 Screw +1.77, Pill +0.67, Tile +0.59 다르다(내가 센 것, 15 부류 절댓값 차 평균 0.28). README 의 ±0.5 판정 폭 안에 99.16 이 들어간다. 부류별 비교에는 이 폭을 쓸 수 없다.
- **PRO 는 정의가 둘 찍혀 있다.** `results.csv` 에 `full_pro`(평균 68.43)와 `anomaly_pro`(94.37)가 있고, README 는 「PRO 는 라이선스 사정으로 코드에 넣지 않았다」 고 적는다. 공개된 `run_patchcore.py` 는 PRO 를 계산하지 않는다. 논문 93.5 와 `anomaly_pro` 94.37 은 0.87 차이라 README 의 ±1.0 폭 경계에 있다. 이 레포는 PRO 를 직접 구현하므로 논문 93.5 에 맞대고, 차이가 나면 정의(거짓 양성률 0.3 적분, 결함 있는 이미지만인지 전체인지)부터 확인한다.
- `sample_training.sh` 의 분할용 IM320 WR50 줄은 주석이 「seed: 39」 인데 명령은 `--seed 22` 다.

**둘. 실행 옵션 (README · `run_patchcore.py`).**

```
python bin/run_patchcore.py --gpu 0 --seed 0 --save_patchcore_model --log_group <이름> --log_project <폴더> results \
  patch_core -b wideresnet50 -le layer2 -le layer3 --faiss_on_gpu \
  --pretrain_embed_dimension 1024 --target_embed_dimension 1024 --anomaly_scorer_num_nn 1 --patchsize 3 \
  sampler -p 0.1 approx_greedy_coreset \
  dataset --resize 256 --imagesize 224 -d bottle ... -d zipper mvtec <datapath>
```

| 이 레포 설정 | 옵션 | 확인한 것 |
|---|---|---|
| 백본 WRN-50-2 | `-b wideresnet50` | `torchvision.models.wide_resnet50_2(pretrained=True)` |
| 백본 ResNet18 | **없음** | `backbones.py` 의 목록 41 개에 `resnet18` 이 없다. `"resnet18": "models.resnet18(pretrained=True)"` 한 줄을 더해야 한다 |
| 층 (2,3) · (1,2,3) | `-le layer2 -le layer3` / `-le layer1 -le layer2 -le layer3` | 조각 격자는 첫 층 기준이라 (1,2,3) 이면 layer1 격자(224 에서 56 x 56 = 3,136 조각)가 되고 뱅크가 4 배다(내가 센 것). 셋을 쌓아도 $d$ 는 1,024 로 풀링된다 |
| 코어셋 1% · 10% | `sampler -p 0.01` / `-p 0.1 approx_greedy_coreset` | 뽑는 수는 `int(N x p)` |
| 이웃 3 | `--patchsize 3` | `torch.nn.Unfold` 에 채우기 `(p-1)/2`. 짝수 $p$ 면 채우기가 내림이라 격자 크기가 줄어든다(코드 셈) |
| 이미지 크기 | `--resize`, `--imagesize` | 아래 셋째 |
| 시드 0 · 1 · 2 | `--seed` | 아래 넷째 |

- `--anomaly_scorer_num_nn` 은 **코드 안에서 버려진다.** `run_patchcore.py` 는 `anomaly_scorer_num_nn=` 로 넘기는데 `PatchCore.load()` 의 인자 이름은 `anomaly_score_num_nn` 이라 `**kwargs` 로 빠지고 기본값 1 이 쓰인다. 이 레포는 1 을 쓰므로 결과에는 상관없다.
- **식 (7) 재가중은 코드에 없다.** 이미지 점수는 조각별 최근접 거리의 최댓값이다. 거리는 faiss `IndexFlatL2` 의 `search` 결과를 그대로 쓴다.
- `requirements.txt` 는 `faiss-cpu` 이고 `faiss-gpu` 줄은 주석이다. `--faiss_on_gpu` 는 faiss 의 GPU 판이 있어야 쓸 수 있다. 백본은 `pretrained=True` 로 부르므로 Colab 의 torchvision 판에서 이 인자가 받아지는지와 어떤 가중치가 오는지 확인할 자리다.
- 원 저자 코드는 부류별 결과를 `results.csv` 에만 남기고 이미지 점수 · 분할 지도는 저장하지 않는다. 이 레포 지표 코드로 재려면 `PatchCore.predict()` 가 돌려주는 `scores` · `segmentations` 를 꺼내 저장하는 줄이 필요하다.

**셋. 전처리 함정.** `datasets/mvtec.py` 는 `transforms.Resize(resize)` 뒤 `transforms.CenterCrop(imagesize)` 다.

- `Resize` 에 정수 하나를 주면 **짧은 변을 그 길이로 맞추고 비율을 지킨다.** MVTec 은 정사각이라 `--resize 256 --imagesize 256` 이면 자르지 않은 256 x 256 이 된다. 정사각이 아닌 이미지(VisA · Real-IAD 에 해당하는지 데이터를 받은 뒤 확인)는 같은 옵션에서도 **긴 변이 가운데 잘린다.** 비교 단계의 「자르지 않음」 을 지키려면 `Resize((256, 256))` 으로 바꾸거나 이미지를 미리 256 x 256 으로 줄여 넣어야 한다. README 의 「데이터 읽기만 덧붙인다」 는 이 변경을 포함해야 한다.
- 정답 가면도 같은 `Resize`(기본 양선형) · `CenterCrop` 을 거친 뒤 `metrics.py` 에서 `.astype(int)` 로 바뀐다. 양선형으로 생긴 0 과 1 사이 값이 0 으로 내려가 가면 가장자리가 줄어든다(코드에서 읽은 동작). 이 레포 지표 코드는 가면을 최근접 보간으로 줄인다.
- 분할 지도와 가면은 원 해상도가 아니라 잘린 입력 크기(224 또는 256)에서 비교된다.
- 256 · 자르지 않음에서 조각 격자는 layer2 기준 32 x 32 = 1,024 개로 224 의 1.31 배다. MVTec 부류 평균 뱅크는 (3,629 / 15) x 1,024 = 247,740 개, layer1 까지 쓰면 64 x 64 = 4,096 조각이라 990,959 개다(내가 센 것).

**넷. 시드가 고정하는 무작위성.** `run_patchcore.py` 는 부류마다 학습 전에 `utils.fix_seeds(seed)` 를 불러 `random` · `numpy` · `torch` · `torch.cuda` 시드를 고정하고 `cudnn.deterministic = True` 로 둔다. `approx_greedy_coreset` 의 무작위 두 곳은 모두 이 시드에 묶인다: 시작점 후보 10 개(`np.random.choice`)와 128 차원 사영 행렬(`torch.nn.Linear` 초기화). **따라서 시드 0 · 1 · 2 가 코어셋 시작점과 사영을 바꾸는 것이 이 레포의 시드 반복이 재는 흩어짐이다.** 코어셋을 쓰지 않으면(`identity`) PatchCore 쪽 무작위는 남지 않는다. 논문은 시드도 반복 수도 적지 않았고, 흩어짐이 붙은 것은 표 S5 하나다.

**다섯. Q1 순위 해석에 쓸 숫자.** 논문의 MVTec 값으로 보면 백본 다섯 x 코어셋 둘의 이미지 AUROC 가 0.5 점 폭에 몰려 있고, 코어셋 1% 와 10% 는 평균으로 0.4 점 안이다(부류별로는 2.3 점까지). 한편 같은 설정에서 원 저자 코드와 논문의 부류 값이 1.77 점까지 다르다. MVTec 에서 PatchCore 네 칸(코어셋 · 백본 차이)의 순위는 시드 흩어짐보다 작은 차이로 정해질 수 있다(내 해석). 층 (1,2,3) 은 이미지 AUROC 를 0.2 ~ 1.09 점 내리는 쪽으로 두 조건에서 같은 방향이다.

**여섯. Q2 에 쓸 숫자.** MVTec 에서 10 장일 때 이미지 AUROC 가 PatchCore-10 −5.4, PaDiM(다시 구현) −12.2 떨어진다. 이 레포 MVTec 결과를 맞댈 기준 칸이다. 원 저자 코드에는 장 수를 고르는 옵션이 없다(`--train_val_split` 은 정렬된 파일 앞에서부터 비율로 자른다). 50 · 10 장을 고르는 법과 시드는 이 레포가 정해야 한다.

**일곱. 지금 확인된 것은 여기까지다.** 논문이 잰 것: WRN-50 (2,3) 의 25 · 10 · 1%, 백본 다섯(ResNet18 없음), WRN-50 · 224 에서 단계 여섯 조합, WRN-101 · 280 에서 (2,3) 대 (1,2,3), 적은 표본 일곱 점, 이미지 크기 여덟 줄, MTD · mSTC 한 설정씩. 논문이 말만 한 것: 재가중이 더 튼튼하다, 코어셋과 근사 탐색을 합치면 더 빠르다, 분할은 크기를 키우면 꾸준히 오른다. 내가 센 것: 부록 표 평균 17 줄 대조, 남긴 % 일곱 칸, 거짓 음성 원인별 개수, 자르기 넓이 비, 조각 · 뱅크 크기, 코드와 논문의 부류별 차이.

## 남는 질문

- **그림 4 의 「코어셋 있음」 은 몇 % 인가.** 그림 4 의 $p$ = 3 PRO 가 코어셋 있음 93.50 · 없음 93.3 이라 표 5 의 10% (93.5) · 100% (93.3) 와 맞는다. 10% 로 읽히지만 적혀 있지 않다.
- **표 S6 의 백본마다 어느 단계를 썼나.** 단계 실험은 WRN-50 에서만 했다.
- **표 S5 의 ± 는 몇 번의 무엇인가, 장 수마다 어떤 이미지를 골랐나.**
- **표 4 의 묶기 방식.** 공개 코드는 모델마다 점수를 최소-최대 정규화한 뒤 평균한다. 논문 표를 낸 방식과 같은지는 논문에 없다.
- **faiss `IndexFlatL2` 가 돌려주는 거리가 제곱 거리인가.** 그렇다면 분할 지도는 제곱 거리를 흐린 것이 된다. faiss 문서에서 확인할 자리다.
- **VisA · Real-IAD 에서 원 저자 코드의 `Resize(정수)` 가 이미지를 어떻게 바꾸는가.** 두 데이터의 이미지 크기를 데이터 논문 · 받은 파일에서 확인한 뒤 정한다.
